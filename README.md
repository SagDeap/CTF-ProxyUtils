# CTF-ProxyUtils

[![Релиз](https://img.shields.io/github/v/release/SagDeap/CTF-ProxyUtils?label=%D1%80%D0%B5%D0%BB%D0%B8%D0%B7)](https://github.com/SagDeap/CTF-ProxyUtils/releases/latest)
[![Лицензия](https://img.shields.io/badge/%D0%BB%D0%B8%D1%86%D0%B5%D0%BD%D0%B7%D0%B8%D1%8F-MIT-blue)](LICENSE)

Утилита для Attack/Defense CTF: найти машины команды в локальной сети и
пробросить на них порты с боевой виртуалки — без ручной возни с `socat`,
`iptables` и SSH-туннелями, когда всё горит.

Один статический бинарник с вшитой веб-панелью. Ноль зависимостей,
ничего не нужно ставить на vulnbox.

```
чекер / атакующие ──▶ vulnbox:7010 ──▶ ноут Пети:7010
                       (ctf-proxyutils)     (тут крутится сервис)
```

## Зачем

Виртуалка умирает или её надо разгрузить, а сервис уже поднят на чьём-то
ноутбуке. Нужно, чтобы трафик с публичного порта виртуалки уходил туда —
быстро, с возможностью так же быстро откатить.

## Возможности

- **Проброс TCP** — правило `слушать порт → слать на хост:порт`, включается
  и выключается одной кнопкой. Живая статистика: соединения, байты в обе
  стороны, время последней активности.
- **Сканер сети** — находит машины в подсети и показывает, что на них
  открыто. Из результата проброс создаётся в один клик.
- **Определение сервисов** — читает баннеры (SSH, HTTP, Redis, FTP, SMTP,
  MySQL, VNC), для веба вытаскивает `Server` и `<title>`.
- **Проверка живости и резерв** — если целевая машина отвалилась, правило
  само уходит на резервный адрес и возвращается обратно, когда основной оживёт.
- **Запись трафика** — всё, что прошло через порт, видно в панели в hex или
  текстом. На A/D это готовый сборник чужих эксплойтов.
- **Защита панели** — токен доступа, по умолчанию слушает только `127.0.0.1`.

## Установка

Готовые бинарники — в [releases](https://github.com/SagDeap/CTF-ProxyUtils/releases/latest).
Они статические: ни Go, ни библиотек на виртуалке не нужно.

```sh
curl -LO https://github.com/SagDeap/CTF-ProxyUtils/releases/latest/download/ctf-proxyutils-linux-amd64
chmod +x ctf-proxyutils-linux-amd64
./ctf-proxyutils-linux-amd64
```

Ссылка `latest/download/…` всегда указывает на свежую версию, так что команду
можно держать в шпаргалке команды и не править от соревнования к соревнованию.

Собраны варианты под `linux` (amd64, arm64, 386, arm), `darwin` (amd64, arm64)
и `windows` (amd64). Контрольные суммы — в `checksums.txt` рядом с бинарниками:

```sh
sha256sum -c checksums.txt --ignore-missing
```

## Сборка из исходников

```sh
make build       # ./ctf-proxyutils под текущую систему
make dist        # статические бинарники под все платформы + checksums.txt
make test        # тесты
```

Требуется Go 1.18+. Для `make dist` нужен официальный toolchain с go.dev —
gccgo кросс-компиляцию не поддерживает.

### Как выпускается релиз

Сборкой занимается GitHub Actions: тег вида `v*` запускает
[workflow](.github/workflows/release.yml), который прогоняет тесты, собирает
все платформы и публикует релиз с файлами.

```sh
git tag v0.1.0
git push origin v0.1.0
```

Собрать релиз можно и вручную — вкладка **Actions** → **Релиз** → **Run workflow**.

## Запуск

```sh
./ctf-proxyutils
```

При первом запуске генерируется токен и печатается ссылка для входа:

```
  CTF-ProxyUtils 0.1.0
  ──────────────────────────────────────────────
  панель:  http://127.0.0.1:8420
  токен:   kJ3nR8vQx2mP5wL9tY7bN4cA
  ссылка:  http://127.0.0.1:8420/#token=kJ3nR8vQx2mP5wL9tY7bN4cA
  ──────────────────────────────────────────────
```

Конфигурация лежит в `config.json` рядом с бинарником и переживает
перезапуск: правила поднимутся сами.

### Флаги

| Флаг | Что делает |
|------|-----------|
| `-addr 127.0.0.1:8420` | адрес панели |
| `-bind-all` | слушать панель на всех интерфейсах |
| `-token СТРОКА` | задать токен вручную |
| `-no-auth` | выключить авторизацию (только доверенная сеть!) |
| `-config ПУТЬ` | путь к файлу конфигурации |
| `-version` | версия |

### Как открыть панель с ноутбука

По умолчанию панель слушает только localhost — на боевой виртуалке с публичным
адресом открытая наружу панель управления пробросами достанется соперникам
вместе с вашими сервисами.

Безопасный способ — SSH-туннель:

```sh
ssh -L 8420:127.0.0.1:8420 user@vulnbox
# панель откроется на http://127.0.0.1:8420 у вас на ноутбуке
```

Если сеть доверенная (например, VPN команды), можно и напрямую:

```sh
./ctf-proxyutils -addr 10.10.0.1:8420   # адрес во внутренней сети
```

## Типовой сценарий

1. Виртуалка сдыхает, сервис поднимаете на ноутбуке — пусть `192.168.0.5:7010`.
2. На виртуалке запускаете `./ctf-proxyutils`, открываете панель.
3. Вкладка **Сканер сети** → подсеть подставляется сама → **Сканировать**.
4. Находите `192.168.0.5`, у порта `7010` жмёте **пробросить**.
5. Порт прослушивания подставится тот же — жмёте **Сохранить**.

Чекер стучится в `vulnbox:7010` и попадает на ноутбук.

Дальше полезно включить в правиле **проверку живости** и указать **резервный
адрес** — второй ноутбук с той же копией сервиса. Если первый уснёт, трафик
уйдёт на резерв сам.

## Порты ниже 1024

Проброс работает в userspace, поэтому root нужен только чтобы занять
привилегированный порт. Вместо запуска всей утилиты от root лучше выдать
бинарнику одну возможность:

```sh
sudo setcap 'cap_net_bind_service=+ep' ./ctf-proxyutils
```

## Устройство

```
cmd/ctf-proxyutils/     точка входа, флаги, graceful shutdown
internal/proxy/         правила, слушатели, пайпы, health-check, запись трафика
internal/scan/          сканер, фингерпринт сервисов, ARP, интерфейсы
internal/config/        конфиг с атомарным сохранением
internal/web/           REST API и вшитая через go:embed панель
```

### API

Все ручки, кроме `/api/ping` и `/api/login`, требуют токен —
в заголовке `X-Auth-Token` либо в куке после входа.

| Метод | Путь | Действие |
|-------|------|----------|
| `GET` | `/api/state` | правила, статистика, состояние скана |
| `GET` `POST` | `/api/rules` | список / создать |
| `GET` `PUT` `DELETE` | `/api/rules/{id}` | получить / изменить / удалить |
| `POST` | `/api/rules/{id}/toggle` | включить или выключить |
| `POST` | `/api/rules/{id}/switch` | вручную уйти на резерв и обратно |
| `POST` | `/api/rules/{id}/reset` | обнулить счётчики |
| `GET` `DELETE` | `/api/rules/{id}/dumps` | записанный трафик / стереть |
| `GET` `POST` `DELETE` | `/api/scan` | состояние / запустить / прервать |
| `GET` | `/api/interfaces` | локальные подсети для формы скана |

Пример — создать проброс из консоли:

```sh
curl -X POST http://127.0.0.1:8420/api/rules \
  -H "X-Auth-Token: ВАШ_ТОКЕН" \
  -H 'Content-Type: application/json' \
  -d '{"name":"сервис","enabled":true,"listen_port":7010,
       "target":{"host":"192.168.0.5","port":7010}}'
```

## Ограничения

- Только TCP. UDP-сервисы на A/D встречаются редко, поддержки пока нет.
- Только IPv4.
- Сканер работает без raw-сокетов и потому без root: живость определяется
  TCP-подключением. Хост, который молча дропает пакеты на всех проверяемых
  портах, найден не будет — помогает расширить список портов.
- MAC-адреса берутся из системной ARP-таблицы (`/proc/net/arp`), то есть
  только на Linux и только для своей L2-сети.
- База вендоров по MAC намеренно короткая — в ней только гипервизоры и
  Raspberry Pi, где префикс достоверен.
